# Loop State

## Layout

```
.mjloop/
├── config.yaml      tracks, limits, verify commands — hand-editable
├── state.json       current run — MCP-owned, never hand-edited
├── INDEX.md         every plan and its status — generated by mjloop_index_render
├── design-system.md what the product looks like — authored, absent until synced
├── runs/<run>/      HALT.md, and per cycle:
│   └── cycle-NN/    roster.json, <agent>.json, findings.json
├── plans/<plan>/    one directory per plan
│   ├── PLAN.md      the plan itself — prose, authored
│   ├── REVIEW.md    plan-critic's objections — prose, authored
│   ├── manifest.json  derived from the story files — MCP-owned
│   └── stories/     one markdown file per story, written through the tools
└── memory/          decisions, lessons and patterns — written by mjloop_memory_add
```

A run directory is named `<run_id>--<story|adhoc>--<track>`, and
`state.history[-1].ref` holds the path — that is what a story's `evidence` points at.

`PLAN.md` carries the plan's identity and its approval decision in frontmatter, with the
plan itself as prose below. `REVIEW.md` is `plan-critic`'s output. Both are authored;
`manifest.json` is derived.

`design-system.md` is extracted from the project by `/mjloop:design-sync`, never generated
and never created at init. It is authored: correct it by hand when the extraction got
something wrong, and re-sync when the code moves.

## One owner

`state.json` and every `manifest.json` are written **only** by the loop MCP server. A
`PreToolUse` hook denies `Write` and `Edit` on them. This is not ceremony: a model
corrupting that JSON loses the entire run, and it is the most common way agent loops
fail in practice.

`config.yaml` is the opposite — it is yours. Edit it freely to change a track's cap,
force a specialist, or set verify commands.

Story files sit between the two. They are prose, so no hook denies a write to one, but
they are still tool-owned: `mjloop_story_add` and `mjloop_story_update` regenerate the plan's
manifest as part of the write, and a hand-edited story leaves the derived state behind.

## Tools

| Need | Tool | Writes |
|---|---|---|
| Provision `.mjloop/` | `mjloop_init` | the directories, `state.json`, `config.yaml` |
| Read the current run | `mjloop_state_get` | — |
| Open a run | `mjloop_run_start` | `state.json`, the run directory |
| Declare the cycle's agents | `mjloop_roster_set` | `cycle-NN/roster.json` |
| Persist an agent result | `mjloop_run_log` | `cycle-NN/<agent>.json`, `state.json` |
| Close a cycle | `mjloop_cycle_advance` | `state.json`, `cycle-NN/findings.json`, `HALT.md` |
| Stop with a report | `mjloop_halt` | `state.json`, `HALT.md` |
| Create a plan | `mjloop_plan_create` | `plans/<plan>/PLAN.md`, its `manifest.json` |
| Record a plan approval | `mjloop_gate_set` | `plans/<plan>/PLAN.md` frontmatter |
| Add a story | `mjloop_story_add` | the story file, its plan's `manifest.json` |
| Change a story | `mjloop_story_update` | the story file, its plan's `manifest.json` |
| Read a story, or resolve `--next` | `mjloop_story_get` | — |
| Rebuild the index | `mjloop_index_render` | `INDEX.md`, every `manifest.json` |
| Record a memory | `mjloop_memory_add` | `memory/<id>-<slug>.md` |
| Search memory | `mjloop_memory_search` | — |
| Read a memory | `mjloop_memory_get` | — |

Nothing else refreshes `INDEX.md`. A story write regenerates its own plan's manifest, so
call `mjloop_index_render` after one if the index is to stay true.

`mjloop_state_get` returns a compact summary rather than the whole file, so the leader's
context does not grow with the cycle count. Read the run directory when you need detail.

Memory entries are prose you may correct by hand, but write them with `mjloop_memory_add`:
it allocates the id and names the file. An entry whose frontmatter no longer matches the
schema is skipped by search until it is repaired — it keeps its id either way, so nothing
overwrites it in the meantime.

## Reading a halted run

`.mjloop/runs/<run>/HALT.md` carries the reason, the cycles attempted, the open findings,
and the recommended next step. Read it before restarting anything.
