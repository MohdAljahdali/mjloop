**Заставьте программных агентов доказать, что работа завершена.**

`mjloop` — плагин Claude Code, который превращает работу агентов в ограниченные циклы,
подкреплённые доказательствами. Руководитель выбирает подходящих агентов, запускает их в
изолированных контекстах и принимает успех только после того, как движок запишет результат
собственных проверочных команд проекта.

`запрос → трек → изолированные агенты → проверка движком → доказанный результат`

> [!IMPORTANT]
> Сейчас `mjloop` поддерживает Claude Code. Адаптеры для других программных агентов пока
> не входят в опубликованный плагин.

## Зачем нужен mjloop?

- **Доказательства вместо уверенности** — заявление об успехе не может перекрыть
  отсутствующую или неуспешную квитанцию движка.
- **Состояние, которое агенты не перепишут** — сервер MCP владеет состоянием запуска и
  производными манифестами.
- **Ограниченная автономность** — лимиты циклов и защита от застоя и повторяющихся ошибок
  останавливают работу без прогресса.
- **Свой процесс для каждой задачи** — короткое изменение, многоцикловая сборка,
  исправление после воспроизведения или проверяемое планирование.

## Быстрый старт

Потребуются Claude Code, Node.js 20 или новее и Git.

```bash
git clone https://github.com/MohdAljahdali/mjloop.git
cd mjloop/engine
npm install
npm run build
cd ..
claude plugin marketplace add "$PWD"
claude plugin install mjloop@mjloop
```

Затем откройте Claude Code в проекте и выполните:

```text
/mjloop:init
/mjloop:edit добавь проверку ввода в форму регистрации
```

> [!NOTE]
> Свежий клон нужно один раз собрать: сервер MCP и CLI хуков запускаются из
> `engine/dist/`. См. [полное руководство по установке](docs/install.md).

## Выберите подходящий трек

| Команда | Лучше всего для | Встроенное правило |
|---|---|---|
| `/mjloop:edit <запрос>` | Небольшие точечные изменения | Один цикл; эскалация при росте объёма |
| `/mjloop:build <цель>` | Функции и крупная реализация | Проверяемые циклы до завершения или остановки |
| `/mjloop:fix <проблема>` | Дефекты и регрессии | Воспроизвести сбой до принятия исправления |
| `/mjloop:plan <идея>` | Превращение идеи в реализуемые истории | Проверка соответствия и одобрение до создания историй |

Используйте `/mjloop:status` для просмотра запуска, `/mjloop:resume` для продолжения,
`/mjloop:stop` для остановки и `/mjloop:web` для открытия панели в браузере.

## Что происходит в цикле?

1. Руководитель собирает команду из выбранного трека и объясняет включение или пропуск каждого специалиста.
2. Агенты с контрактами работают в изолированных контекстах с чёткими обязанностями.
3. Движок выполняет команды, зафиксированные при старте, и хранит полный журнал отдельно от рассказа агента.
4. Неудачная проверка становится входом следующего цикла; успешная квитанция может закрыть запуск.
5. Защита останавливает циклы при достижении лимита, застое или повторении той же ошибки.

## Больше, чем выполнение

- **Исследование функции** — навык `mjloop-feature-discovery` задаёт по одному вопросу и
  останавливается на брифе, который может одобрить человек.
- **Маршрутизация с учётом проекта** — принятые карты компонентов и навыки направляют
  фиксированные роли, не меняя текущий запуск.
- **Панель в браузере** — просматривайте запуски, планы, истории, доказательства,
  конфигурацию и память через `/mjloop:web`.
- **Расширяемые треки** — добавляйте агента, навык или трек через `/mjloop:add`.

> [!TIP]
> Начните с `/mjloop:edit` для реального ограниченного изменения. Это самый быстрый способ
> увидеть контракт проверки без затрат на несколько циклов.
